# Shangou virtual motion compatibility

The tested enterprise IPA (UUID `5431157E-3050-3D18-ADF1-D0D62D65C0F9`, 12.10.61 / 59536680) crashes on macOS build `26B123` while destroying `UINSVirtualMotionDevice`: an over-resumed dispatch source or a stale object captured by its initialization blocks. The crash recorder can subsequently suspend a thread holding the Objective-C runtime lock and deadlock, presenting as a frozen logout page.

Only for this binary, host build (`26B123`, `23C71` or `24G517`) and presence of the Mac virtual device, `CMMotionManager` allocation returns nil before creating any CoreMotion instance. Calls to the unavailable manager therefore return nil/NO under normal Objective-C semantics. No sensor readings are fabricated. CoreLocation, account storage and crash reporting remain untouched. Revalidate other versions rather than broadening the match by bundle ID.

Run `sh Tests/ShangouMotion/run.sh`. It checks mismatching image/host guards, the alloc/init, new and allocWithZone paths, with no allocated instance or initializer/destructor invocation. Actual app launch, logout and page interaction must also be verified; these checks do not emulate UIKitMacHelper. Discarded approaches: returning nil from the initializer still destroys an uninitialized CoreMotion object; only disabling updates still leaves virtual-device teardown alive. Neither is sufficient.

On `23C71` (macOS 14.2.1), the post-location-authorization sample shows the CoreMotion thread stopped in an object call and KSCrash waiting for the allocator lock after suspending other threads. This matches the earlier virtual-device failure pattern; the original exception and old-host retest are still required for final acceptance. Unknown macOS builds, another IPA UUID and a missing virtual device must retain their normal motion behavior.

The 2026-11-09 diagnostic bundle confirms the same IPA on `24G517` (macOS 15.7.4) terminates with `EXC_BREAKPOINT / SIGTRAP` on `com.apple.CoreMotion.MotionThread`, through `_dispatch_lane_resume` and `-[UINSVirtualMotionDevice dealloc]`. The loaded PlayTools UUID matches the published component; the missing host-build guard caused the protection to be skipped. Tests cover this build, both adjacent unknown builds, a missing virtual device and another IPA UUID. Native tests do not replace an upgrade/retest on the affected Mac.
