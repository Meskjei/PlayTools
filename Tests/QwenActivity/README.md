# Qwen ActivityKit compatibility

The macOS 14.2.1 / 23C71 crash of Qwen 6.12.0.2486 (UUID `282EE888-852E-3C5B-8F40-91820B039B6F`) resolves the generic type at cache `0x11116af40`, through `0xb32578` and `0xb422b4`, on a Swift async task. Its indirect symbolic reference targets the weak GOT import of `ActivityKit.Activity.PushTokenUpdates.Iterator` at `0x10f0d2780`. The accompanying Activity/PushTokenUpdates imports are also weak. The original report has no ActivityKit image loaded. This is separate from the earlier Qwen Block descriptor failure and the Shangou Live Activity guard.

`QWGaoDeLiveActivityService.startTokenObservation` and `QWLiveActivityManager.startAll` are void methods. Their Objective-C wrappers and Swift callers reach checked ARM64 indirection thunks. Only for the exact UUID, missing ActivityKit metadata, original thunk instructions, expected implementation addresses, and writable `__DATA,__br_tb` slots, replace those two process-local function pointers with a void leaf. The data table is already writable: no page permissions, signed code, IPA, system Swift metadata, class tables, account or other callbacks are changed. If ActivityKit is available or any fingerprint differs, leave the application unchanged.

`sh Tests/QwenActivity/run.sh` checks UUID, capability combinations, section boundaries/overflow, ASLR, instruction mismatches, pointer replacement/idempotence, ordinary invocation, and refusal to write a read-only page. Existing Qwen Block, Shangou Live Activity/Motion/Tab checks also run. Native framework builds use the project's FASTLANE release path (SwiftLint is absent; this change has no Swift edits). Guard tests and a newer Mac's UI check do not replace the original macOS 14.2.1 user's upgrade/retest.
